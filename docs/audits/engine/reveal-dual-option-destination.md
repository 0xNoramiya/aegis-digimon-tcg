# Reveal destinations for DUAL cards

`RevealAdd` can offer alternative destinations for a selected revealed card. A DUAL card has both Digimon and Option kinds, but cannot be played as a Digimon: the local rules manual's Dual cards section states that these cards have no play costs and cannot be played as Digimon. A printed play-or-use effect must therefore retain the Option-use destination and exclude play.

The destination filter in `actions/reveal.ts` now excludes Option cards from play choices. This preserves ordinary Digimon and Tamer play destinations and the existing Option execution lifecycle, including color requirements, cost handling, and Arts Digivolve.

The replay behind GitHub issue #5528 (in-game report 248) reproduced all 64 inputs without divergence before the fix. Input 51 selected LM-067; input 52 selected the incorrectly offered play destination, which staged the card into hand before the engine rejected playing a DUAL card. The behavior-named replay fixture is trimmed through input 52. Its regression continues from the selection boundary; a shared minimal fixture proves free Option use, De-Digivolve, final trash placement, and completion without a pending decision. The Chromium regression drives the same fixture through the real client.

The effects snapshot sweep found four affected destination paths across three cards. LM-067's When Digivolving and Counter paths can reach both LM-067 and BT25-085 today and share the corrected behavior. BT26-084's Seven Code path and BT21-087's Vemmon path are latent for DUAL cards: the committed catalog has no matching DUAL card. No additional card IR changes are necessary. Existing tests for those peers and ordinary reveal-play exclusions protect the other destinations.

Evidence limits: the report is an in-game GitHub issue with no comments or linked Discord thread, and no Discord bug connector was available. The official LM-067 image URLs in both English and Japanese returned HTTP 404 during verification; printed text was checked against the committed catalog and digimoncard.io, while the DUAL restriction is explicit in `data/kb/rules/manual.md`. The local card-specific KB query returned no entries. This is a focused destination audit, not a claim of exhaustive LM-067 card fidelity.

Validation: both regressions fail with the destination guard removed and pass with it restored. The LM set, affected peers, existing reveal regressions, and focused reveal mechanisms passed (768 tests in the first run, 23 in the second, with the new regression repeated). Workspace typechecking, full lint/format checking, and diff whitespace validation passed. The Chromium test passed its selection, De-Digivolve, memory, and final-zone assertions, then failed the final health check because the image mirror returns HTTP 404 for `/assets/card-images/LM-067.webp`; the trace attributes all 15 console errors to that missing asset. Browser health is therefore not claimed as passing.
