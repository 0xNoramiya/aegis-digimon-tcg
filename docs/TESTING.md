# Regression fixtures

Name regressions after the behavior they protect, using kebab-case. A report's
Discord, database, or GitHub identity is optional provenance in a comment, not a
filename, scenario ID, suite title, or arena label. Official card IDs identify the
exact card version and remain part of the board specification. Rule citations and
technical replay identities retain their existing purpose.

## Files and responsibilities

Use the smallest set needed for the behavior:

```text
apps/api/src/engine/scenarios/<behavior>.test.ts
apps/api/src/engine/scenarios/<behavior>.fixture.ts      # reusable preparation, when needed
apps/api/src/engine/scenarios/<behavior>.replay.json     # trimmed recorded reproduction, when available
apps/web/e2e/<behavior>.spec.ts                          # when browser behavior needs coverage
```

The fixture exports plain data or a factory returning `ScenarioFixture`, without
Vitest, Playwright, assertions, or automatically executed game actions. A default
export supplies the variant opened by the local command. An example is
[`invasion-titans-drawn-ogre-discard.fixture.ts`](../apps/api/src/engine/scenarios/invasion-titans-drawn-ogre-discard.fixture.ts).

`engine/scenario/board.ts` materializes `BoardSpec` through the engine's state
mutation helpers. The testkit reuses it; its existing imports remain compatible.
`ScenarioFixture` adds explicit memory, turn seat, turn count, and whether this is
the first player's first turn. It represents a position **before the next turn
starts**. The real turn loop increments `turnCount`, unsuspends, draws, and opens
Breeding before Main. Include the initial turn draw in the deck; a fixture is not
a snapshot already paused in Main. Permanents are established by default;
`enteredThisTurn` in a scenario fixture marks entry during the upcoming turn.
Memory is turn-relative: positive favors `turnSeat`, including when seat 1 starts.

Use `{ card: "BT24-045", as: "newlyDrawnOgre" }` to give a card a semantic alias.
Aliases must be unique across both players, zones, stacks, and links. Exact IDs
are generated by the board builder and must not be copied into test code.

## API and browser tests

API tests call `setupScenario(fixture, options)` from `engine/testkit`, start the
real turn loop, and send public intents. Aliases resolve with `s.inst(alias)` and
`s.perm(alias)`. Assert costs, identities, destinations, effect order, relevant
negative branches, and turn progression. Finish the loop with a public surrender
intent in cleanup, including after a failed assertion.

Browser tests import the same fixture and call:

```ts
const refs = await scenario.openFixture(fixture);
const ogreId = refs.instanceId("newlyDrawnOgre");
```

The browser server configures the fixture in its own process, then starts the real
AegisRoom. The browser sends only the generic `local-fixture` name; it cannot send
an arbitrary board to the API. References resolve instance and seeded permanent
IDs before the room starts. Tests still drive visible controls and use synchronized
snapshots as read-only evidence. `openFixture` ends the human's Breeding phase;
an opponent-turn fixture leaves that flow to the configured bot policy.

Keep API and browser actions and assertions separate. Share preparation, not an
assertion script that bypasses either runner's real interface. E2E is useful when
the protected behavior includes prompts, presentation, animation queue completion,
or synchronization. A rules-only regression need not duplicate every variant in
the browser. Reuse `scenario.healthy()` and the timing guidance in
[`apps/web/e2e/README.md`](../apps/web/e2e/README.md).

The avatar regression allows five seconds for the profile's first lazy mount,
which also loads ReplayViewer and GameScreen dependencies.

Recorded reproductions still use the existing replay tooling and divergence checks
from `AGENTS.md`. Preserve seeds, recorded identities, server revisions, and input
order in the trimmed record. Read recorded intent identities from the fixture
instead of repeating opaque IDs in the test. Assert the corrected behavior after
the failing input; matching the old recording alone is not regression coverage.

## Open a temporary reproduction

From the repository root, with the Node and pnpm versions in `package.json`:

```sh
pnpm scenario open invasion-titans-drawn-ogre-discard
pnpm scenario open .local/scenarios/my-experiment.fixture.ts
pnpm scenario open invasion-titans-drawn-ogre-discard --lab
```

The command builds shared contracts and the API runtime, starts a loopback
Colyseus server and Vite, and opens the real GameScreen in your browser. Reload
the page to restart the position. Stop the runner with Ctrl+C. `--no-open` prints
the URL without opening a browser. The fixture is loaded when the runner starts;
restart the runner after changing it.

Default ports are 4175 (Vite), 2569 (TCP edge), and 2570 (Colyseus). Run one local
runner or Playwright instance at a time. Override them together with
`AEGIS_E2E_WEB_PORT`, `AEGIS_E2E_EDGE_PORT`, and `AEGIS_E2E_SERVER_PORT` if needed.
The opponent's autonomous play stops two turns after the fixture's initial
`turnCount`; reactive decisions stay real. For E2E fixture runs,
`holdBotAfterTurn` is relative to that initial count. Fixtures may declare opponent
intents and decision preferences in `presentation.opponent` when a regression needs
a specific response. Initial restrictions belong in `effects`, applied by the same
preparation code in API tests and rooms.
This runner supports local debugging, not bot-versus-bot match playback.

`.local/scenarios/` is git-ignored. An experiment can default-export a new fixture
or import an existing factory and change its parameters. Commit the fixture only
when it is useful preparation for a regression. There is no scenario catalog or
per-case registration in the room loader, client join types, or the arena interface.
The generic loader is unavailable in production.

## Portable preparation

Fixture matches record their canonical preparation as `startScenarioFixture`. A replay
contains the board, initial effects, and opponent presentation policy, so playback
does not depend on a local fixture registry. Unknown author metadata is stripped.

Migrated positions that intentionally depend on the selected deck use `dealtCards`
recipes with explicit physical indices and a fallback test deck. New regressions
should prefer explicit card identities and semantic aliases for relevant cards.

Use `--lab` to open the same position with the effects inspector and pacing controls.
The permanent arena retains its visual demo; regression fixtures are opened on demand.
